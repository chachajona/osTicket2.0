# AI Draft Implementation Plan

**Status:** Implemented

**Goal:** Provide staff with an AI-assisted reply drafting flow in the ticket composer, streaming draft text into a preview before the staff member explicitly inserts it into the rich text editor.

**Architecture:** `POST /scp/tickets/{ticket}/draft/ai` authorizes reply access, validates the staff prompt, and returns Server-Sent Events. `AiDraftService` selects the configured provider and normalizes its streaming deltas into text chunks. `AiDraftModal` reads those events, renders an incremental preview, and inserts accepted text into TipTap as escaped HTML paragraphs.

**Providers:** Anthropic, OpenAI, and Google Gemini are supported through raw HTTP streaming requests without provider SDK dependencies.

## Configuration

The active provider is selected with `AI_PROVIDER`. The implementation defines a provider map in `config/ai.php`:

| Provider | Credential Environment Key | Endpoint Shape | Default Model When No Override Is Set |
| --- | --- | --- | --- |
| `anthropic` | `AI_API_KEY` | `/v1/messages` | `claude-sonnet-4-6` |
| `openai` | `OPENAI_API_KEY` | `/v1/chat/completions` | `gpt-4o` |
| `gemini` | `GEMINI_API_KEY` | `/v1beta/models/{model}:streamGenerateContent` | `gemini-2.0-flash` |

`AI_MODEL` is an optional active-provider model override. Leave it unset to use the configured provider default.

```dotenv
AI_PROVIDER=anthropic
AI_API_KEY=
AI_MODEL=
OPENAI_API_KEY=
GEMINI_API_KEY=
```

## Backend Flow

1. A staff user submits a prompt to `POST /scp/tickets/{ticket}/draft/ai`.
2. `AiDraftController::store()` authorizes `postReply` access and validates a required string prompt with a 500-character maximum.
3. The controller calls `AiDraftService::stream()` and forwards each returned chunk as an SSE JSON payload:

```text
data: {"text":"Thank you for contacting support."}
```

4. On a provider exception, the controller emits an error payload while retaining the streaming response contract. HTTP `429` failures surface a quota-specific message.

```text
data: {"error":"AI quota exceeded. Please try again later."}
```

## Provider Handling

`AiDraftService` builds a shared system prompt from the ticket subject and the most recent five customer/reply thread entries, capped to a 3,000-character context excerpt.

| Provider | Authentication | Request Content | Parsed Stream Delta |
| --- | --- | --- | --- |
| Anthropic | `x-api-key` plus `anthropic-version` header | System prompt plus user message | `content_block_delta.delta.text` |
| OpenAI | Bearer authorization header | System and user chat messages | `choices[0].delta.content` |
| Gemini | API key query parameter | Combined system context and user prompt in `contents` | `candidates[0].content.parts[0].text` |

OpenAI streaming terminates on the `[DONE]` sentinel. Anthropic and Gemini streams are read until their response bodies end. All provider HTTP failures become `RuntimeException` instances with the provider HTTP status code so the controller can present an appropriate SSE error event.

## Frontend Flow

1. `ReplyComposer` opens `AiDraftModal` from the AI drafting command.
2. The modal sends the prompt with a CSRF-protected `fetch()` request accepting `text/event-stream`.
3. A `ReadableStream` reader consumes SSE lines and appends `text` payloads into a live preview.
4. Provider errors appear inline without modifying composer content.
5. Selecting **Use this draft** HTML-escapes the generated text, preserves paragraphs and line breaks, and inserts the result into TipTap.
6. Selecting **Discard** or closing the modal aborts any active stream and leaves the reply unchanged.

## Security And Behavior

- The endpoint requires the same `postReply` authorization used for normal staff replies.
- The request validates prompt length server-side before opening a provider stream.
- Generated text is previewed before insertion; it is never automatically sent to the customer.
- Generated plain text is escaped before insertion into rich HTML editor content.
- Closing or superseding a generation request aborts the browser request.
